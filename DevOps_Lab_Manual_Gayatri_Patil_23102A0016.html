    4. Likely Viva Voce Questions & Answers for Task 2

    Q1: What is the difference between Agile and DevOps?

    *Answer:* Agile focuses on iteratively developing and delivering software through user stories and collaboration between developers and product owners. DevOps extends Agile by bridging the gap between development and operations through automation (continuous integration, automated testing, containerization, and monitoring).

    Q2: What is the difference between a Product Backlog and a Sprint Backlog?

    *Answer:* The Product Backlog is an prioritized list of all features and requirements for the entire product. The Sprint Backlog is a specific subset of backlog items selected for completion in the current sprint.

    Q3: Why is a Definition of Done (DoD) critical in DevOps?

    *Answer:* Without a strict DoD, code might be labeled "done" when coding finishes, even if it has no automated tests or breaks during deployment. DoD ensures that testing, packaging, and health verification are completed before code is released.

    4. Likely Viva Voce Questions & Answers for Task 3

    Q1: Why did you choose Maven over Gradle?

    *Answer:* Maven enforces a standard project directory structure (src/main/java, src/test/java) and declarative XML configuration (pom.xml). It integrates natively with the Maven Surefire Plugin to produce JUnit XML reports that Jenkins consumes directly.

    Q2: What is Spring Boot Actuator?

    *Answer:* Spring Boot Actuator provides production-ready monitoring and telemetry endpoints (like /actuator/health and /actuator/info) that allow container orchestrators (Docker, Kubernetes) and CI/CD pipelines to verify application readiness without writing manual monitoring code.

    Q3: How does the H2 in-memory database work?

    *Answer:* H2 is an embedded relational database written in Java. When configured with jdbc:h2:mem:vaxdb, it runs inside the Java Virtual Machine (JVM) memory. It requires zero configuration, zero ports, and is destroyed and recreated automatically during test execution.

    4. Likely Viva Voce Questions & Answers for Task 5

    Q1: What does git merge --no-ff do?

    *Answer:* The --no-ff (no fast-forward) flag forces Git to create a dedicated merge commit, even if the target branch could have fast-forwarded. This preserves the historical record of the feature branch and pull request in the Git graph.

    Q2: How does the application determine if a vaccination is OVERDUE?

    *Answer:* When computing the schedule, the engine compares the vaccine's milestone date against LocalDate.now().minusDays(7). If the due date is in the past by more than 7 days, its status is set to OVERDUE.

    Q3: Why use Pull Requests in Agile/DevOps teams?

    *Answer:* Pull Requests facilitate mandatory peer code review, automated CI testing, discussion on architectural choices, and documentation before code is merged into the shared codebase.

    4. Likely Viva Voce Questions & Answers for Task 6

    Q1: What creates a Git merge conflict?

    *Answer:* A merge conflict occurs when two branches make different changes to the same line(s) of a file, or one branch deletes a file that another branch modified. Git cannot automatically decide which change to keep and asks the developer to resolve it manually.

    Q2: What is the difference between a lightweight tag and an annotated tag in Git?

    *Answer:* A lightweight tag is simply a pointer to a specific commit. An annotated tag (created with git tag -a) is stored as a full object in the Git database containing the tagger name, email, date, and a release message. We used an annotated tag for v1.0.0.

    Q3: How do role-based permissions work in your MVP?

    *Answer:* In Parent View, the interface is read-only; clinical administration buttons are hidden. Switching to Healthcare Worker mode unlocks the [💉 Administer] buttons to record the nurse's name, vaccine batch number, and mark doses COMPLETED.

    Q1: What is the primary difference between Unit Testing and Selenium WebDriver Testing in DevOps?

    Q2: What is a Quality Gate in Jenkins and why is it essential?

    *Answer:* A Quality Gate is an automated threshold configured in the CI/CD pipeline. In our pipeline, if any Selenium test assertion fails, the build halts immediately, captures a failure screenshot into target/screenshots/, and skips packaging and Docker deployment to ensure broken code never reaches users.

    Q3: How does your Docker setup support modern microservices best practices?

    *Answer:* We implemented a multi-stage Dockerfile using Eclipse Temurin JDK 21 for building and Alpine JRE 21 for execution, shrinking image size to 214MB. We enforced container security by running under an unprivileged user (vaxuser:vaxgroup) and configured container health checks (/api/health).

    Q4: What is Idempotency in Ansible and how did you prove it?

    *Answer:* Idempotency guarantees that executing an automation playbook multiple times leaves the system in the exact same state without unintended side effects. We proved it by running ansible/playbook.yml twice: the first run made 12 changes, and the second run reported changed=0, proving complete idempotency.

    Q5: How does your rollback mechanism work?

    *Answer:* We developed ansible/rollback.yml. Application versions are preserved in /opt/vaccination-portal/releases/.
